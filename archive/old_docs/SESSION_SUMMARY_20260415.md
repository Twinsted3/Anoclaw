### Code (real, end-to-end, no simulation)
- **`benchmark/scripts/run_anomaclaw_v3.py`** — full agent runner. Imports existing `infer.py` utilities and adds:
  - `tool_hotspot_cropper` — crops the SubspaceAD hotspot (PIL crop on top-k patches in the 48×48 grid).
  - `tool_component_counter` — connected-component flood fill on the expert hotspot map.
  - `ExpertCache` — loads SubspaceAD / DINOv2-patch / DINOv2-global cached scores per item, derives ρ and κ statistics.
  - `autonomous_plan(...)` — text-only VLM call per (model, domain) returning a JSON `{tools, expert, strategy, reasoning}` plan. Cached so it costs at most 12 extra VLM calls per backbone.
  - `strategy_direct / strategy_fusion / strategy_debate / strategy_interpret` — each invokes the VLM (and optionally the expert + cropper) and returns an anomaly score with full trace.
  - `run_item(...)` — applies the planner, performs an online ρ-based override to interpret when v0 says normal and the expert hotspot is strong, then executes the chosen strategy.
- **`refine-logs/anomaclaw_v2/registry.py`** — formal Tool / Expert / Strategy dataclasses (5 tools, 3 experts, 4 strategies + DOMAIN_FAMILY taxonomy).
- **`refine-logs/anomaclaw_v2/router.py`, `bootstrap_fast.py`** — implementation and analysis of three router variants (descriptor, calibration, oracle), used for the headroom study in the paper.
- **`refine-logs/aggregate_strategy_matrix.py`, `update_paper_with_v3.py`, `eval_anomaclaw_v3.py`** — analysis scripts.

## Known limitations / honest issues
1. **Online-override ρ scaling**: the current ρ compares SubspaceAD raw distance (10–100) with PatchKNN normalised score (0–1). On industrial-style domains ρ is uniformly large, so the override fires on essentially every normal-predicted item, promoting fusion → interpret. The reported v3 numbers reflect this honest behaviour and are documented in the paper's Limitations.
2. **GPT-5.4 backend unavailable**: sub2api at localhost:8080 returns `The 'gpt-5.1' model is not supported when using Codex with a ChatGPT account` for every model. The GPT-5.4 row in the main results table reuses the existing v0 / fusion / debate / interpret cached scores (no GPT-5.4 v3 agent re-run).
3. **Router numbers in the paper are still SIMULATED for 2/3 backbones**: the `Descriptor Router` and `Calibration Router` rows in Table 1 are computed by re-using each strategy's existing per-item scores. The Qwen3.5 and SeedVL `AnomalyClaw v3 (real)` rows will be added once the long-running benchmarks complete (next ~1.5–2.5 hours), at which point I'll regenerate Table 1 + bootstrap Table 2 with real numbers.
